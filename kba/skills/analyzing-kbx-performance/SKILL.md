# 成果を見る

数字を並べて終わりにしない。**記述 → 診断 → 処方**の順で進め、最後に「次に何を直すか」を出す。

## 最初にすること

```
kba_get_skill_guidance({ topic: "analysis" })
```

指標の定義、派生指標の計算、最小ボリュームの扱い、優先順位の付け方はここにある。
このファイルより guidance が新しい。食い違ったら guidance に従う。

## 手順

```
- [ ] 1. まず処方を見る    kba_get_kbox_ops_recommendations
- [ ] 2. 根拠を掘る        kba_get_kbox_analytics_snapshot
- [ ] 3. 現物で裏を取る    kba_list_kbox_csv_artifacts → rows
- [ ] 4. 優先度を付けて示す
```

**1.** `kba_get_kbox_ops_recommendations` が、同じ絞り込みに対する推奨を返す。ここから始めると速い。

**2.** `kba_get_kbox_analytics_snapshot` が根拠になる集計を返す。処方の裏付けが要るとき、
あるいは推奨と見立てが食い違うときに使う。

**3.** 「なぜその求人が弱いのか」は原稿を見ないと分からないことが多い。
`kba_list_kbox_csv_artifacts` で現在の掲載状態を選び、`kba_get_kbox_csv_artifact_rows` で
必要な求人・列だけを取る。全件が要るときだけ `kba_get_kbox_csv_artifact_download_url`。

**4.** 定期の報告が要るなら `kba_generate_daily_ops_report` / `kba_generate_weekly_ops_report`。

## 診断の型

**ファネルを分解する。** 表示 → クリック → 応募 のどこで落ちているかを、率ではなく**絶対数の損失**で
特定する。率だけ見ると母数の小さい求人が上位に来る。

**落ちている段階で原因の方向が決まる。**

| 落ちる段階 | 主に効く打ち手 |
|---|---|
| 表示が少ない | 職種区分・キーワード・掲載状態 |
| クリックされない | タイトル・給与の見せ方・写真 |
| 応募されない | 仕事内容・応募条件の広さ・選考の重さ |

**セグメントに分ける。** 全体の平均で断定しない。クライアント別・職種別・エリア別に割ると、
特定の塊だけが悪いことが多い。

**小さい分母の率は結論に使わない。** 参考値として扱い、そう明示する。

**掲載保留を見落とさない。** 出ていない求人は、原稿をいくら直しても数字が動かない。

## 守ること

**取れない数字を作らない。** 求人単位の費用やクリック単価のように取得できないものがある。
「分からない」と言う。推定値を実測のように示さない。

**記述で止めない。** 「クリック率が下がっています」だけで終えない。どこで、どれだけ、なぜ、
次に何を、まで出す。

**比較の第一基準は自社の過去期間。** 外部の一般的な水準は職種・地域・媒体で大きく動くので鵜呑みに
しない。第二基準は同じ範囲内の相対比較。

**他のクライアントの数字を横断して混ぜない。** 利用者が対象を明示した範囲だけを見る。

**応募数は概算で日次。** 数字が古い(1 日以上前の)場合は、KBA の「媒体運用」画面で対象の接続の「今すぐ更新」を
実行してもらってから評価する。

**効果測定は同じ条件で。** 直したあとは、同じ期間・同じ絞り込みで測り直す。数週間は見る。

## 出し方

優先度は **絶対的な機会の大きさ × 見込める改善幅 × 実行のしやすさ** で並べる。
上位いくつかに絞って、それぞれ「何を」「どう直すか」まで書く。全部を並べない。

修正に進むなら revising-and-submitting-kbx-jobs、作り直すなら rotating-kbx-jobs へ渡す。
