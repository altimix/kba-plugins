# 入稿がうまくいかないとき

症状ごとの対処。**原因の内訳をここで説明しない。** 権限や本番設定で止まった場合は、返ってきた理由を
そのまま利用者へ伝え、運用者に確認してもらう。利用者に設定変更を依頼しない。

## Contents

- 承認・レビューがやり直しになる
- 送信が止まる
- アップロードが通らない
- 求人ボックス側で確定しない
- 状態を確認する

## 承認・レビューがやり直しになる

| 症状 | 対処 |
|---|---|
| レビューが見つからない / 期限切れ | レビューを取り直す(直接 CSV は `kba_csv_upload_review`) |
| レビュー後に内容が変わった | 取り直してから再度承認する |
| 承認後に状態が変わった | 送信をやり直し、**新しい承認画面の内容を確認してから**承認する。ファイル自体が変わっていなければ再アップロードは不要 |

承認画面の内容が前回と違って見えるときは、内容が変わったか実行条件が変わったかのどちらか。
**中身を読まずに承認しない。**

## 送信が止まる

| 症状 | 対処 |
|---|---|
| 停止要因があると言われる | 構造・security・整合性の問題。内容の警告ではこの応答にはならない |
| 送信先アカウントが許可されていない | 対象が意図した本番アカウントか先に確認する。合っていれば運用者へ |
| 本番書き込みが無効と言われる | 運用者へ。返ってきた理由をそのまま伝える |

**内容の警告だけで止まることはない。** 止まっているなら別の理由がある。

## アップロードが通らない

| 症状 | 対処 |
|---|---|
| 同じ URL へ2回 PUT した | URL を取り直す。**PUT は1回だけ** |
| 対象クライアントと参照が食い違う | 引数のクライアントとアップロード参照を揃える |
| ファイルが大きい / 行数が多い | 上限は `kba_get_skill_guidance({ topic: "csv-spec" })` |

## 求人ボックス側で確定しない

入稿は2段階で確定する。① 送信 → 確認ページ(件数表示) → ② 利用規約と掲載ガイドラインに同意して更新。

確認ページで止まったまま確定しない場合は、送信をやり直す。件数が想定と違うときは**確定せずに**
中身を確認する。

## 状態を確認する

- 進行状況: `kba_get_job_status`
- 履歴から探す: `kba_list_upload_jobs`
- 求人ボックス側の実データ: `kba_list_kbox_csv_artifacts` → `kba_get_kbox_csv_artifact_rows`
- 表示が古い: KBA の「媒体運用」画面で対象の接続の「今すぐ更新」を実行してもらい、`kba_get_monitor_run` で完了を待つ。
  求人ボックス上の原稿は毎時(件数が動いたクライアント)と 1 日 1 回(全クライアント)自動で取り直される

## 使わない経路

`kba_upload_csv_text` は外部で作った小さい CSV 本文を直接渡す旧経路。**通常は使わない。**
ファイル本文を会話に載せることになり、署名付き URL 経路と役割が重複する。外部ファイルは
`kba_csv_upload_create_url` からの参照渡しを使う。
