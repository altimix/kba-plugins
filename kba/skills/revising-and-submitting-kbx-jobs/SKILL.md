# 直して、入れる

内容の修正から本番入稿までを担う。**修正と送信は別の操作**で、直しただけでは求人ボックスには出ない。

## 最初にすること

```
kba_get_skill_guidance({ topic: "review-sheet-edit" })   # 直すとき
kba_get_skill_guidance({ topic: "upload" })              # 入れるとき
```

このファイルより guidance が新しい。食い違ったら guidance に従う。

## どちらの経路か

| 状況 | 経路 |
|---|---|
| KBA で作った原稿を直す・入れる | **レビューシート経路**(下記) |
| 外部で完成済みの CSV を入れるだけ | 直接 CSV 経路(下記) |

生成物はシートが正本なので、**KBA で作ったものを直接 CSV 経路へ流さない。**

## 直す(レビューシート)

```
- [ ] 1. 対象を確認する
- [ ] 2. preview で差分を出す
- [ ] 3. 人が before/after を確認する
- [ ] 4. apply で反映する
```

**1.** `kba_get_review_sheet` でシートの場所を確認。行の中身は `kba_get_review_sheet_import_rows`。
検証結果を見るなら `kba_get_validation_result`。

**2.** `kba_preview_review_sheet_edits`。**書き込まずに**行・列ごとの before/after、警告、公開への
影響、preview handle を返す。

行の指定は **stable row ID**(推奨)／シートの行番号／列の完全一致セレクタ。既定は `match:"unique"` で、
複数該当したら候補を返して止まる。**黙って対象を広げない。**「全部」は利用者が明示したときだけ使い、
件数を示してから実行する。

**3.** 人が確認する。**この確認を飛ばさない。**

**4.** `kba_apply_review_sheet_edits` に承認済みの preview handle を渡す。1回の batch でシートへ書き、
stable row ID で事後検証する。不確実な結果が返ったときに自動で再試行しない。もう一度の明示承認と理由が要る。

## 入れる(レビューシート正本)

```
- [ ] 1. kba_import_review_sheet     最新のシートを取り込む
- [ ] 2. kba_review_sheet_submit_prepare   人向けの要約を出す
- [ ] 3. 人が承認する
- [ ] 4. kba_review_sheet_submit_confirm   本番キューへ送る
```

prepare は会社名・対象行数・求人ステータス・警告・送信先・取得時刻だけを人に示す。confirm は
不透明なハンドルと承認だけを受け取り、サーバ側で対象・ハッシュ・期限・再送を検証する。
**承認以外では本番キューに送らない。**

## 入れる(直接 CSV・外部で作った完成ファイル)

```
- [ ] 1. kba_csv_upload_create_url    署名付きURLを取る
- [ ] 2. raw bytes を1回だけ PUT      会話にファイル本文を載せない
- [ ] 3. kba_csv_upload_review        内容を確認し承認を記録する
- [ ] 4. kba_csv_upload_submit        本番へ中継する
```

写真 ID を付けてから入れる場合は、3 の前に `kba_prepare_photo_csv_upload` を挟む。
写真の用意そのものは preparing-kbx-photos。

**PUT は1回だけ。** 同じファイルを別の経路へ再送しない。

## 守ること

**内容の指摘は停止要因ではない。** 法令・媒体仕様・文字数・選択肢・既存求人との差分といった指摘は、
行・列・理由・推奨対応として示す。利用者は**直すか「このまま進む」かを選べる。** 可否の最終判断は
求人ボックス側の応答で確認する。

**停止要因は別物。** `canSubmit=false` が表すのは、構造の破損・security・対象の範囲・content hash・
期限・再送・人の承認といった実行上のゲートだけ。**内容の警告がこれになることはない。**

**利用者が指定した値をそのまま入れる。** 内容上の理由で言い換え・空欄化・既定値化しない。警告を確認
して進む場合も、指定された文字列をそのまま反映する。

**求人ステータスは CSV の値をそのまま使う。** 公開 / 下書き / 募集停止。空欄や想定外の値は警告として
示すだけで、勝手に補完しない。

**編集の正本は Google レビューシート。** 生成結果のスナップショットを直接書き換えない。

**経路を混ぜない。** 同じ CSV を複数の経路へ二重に送らない。各ツールが成功したら、返ってきた次の手順
だけを続行し、前段のファイル本文を再送しない。

**ID を人に転記させない。** 返ってきた ID・ハンドル・ハッシュは内部でそのまま引き回す。

**本番送信には人の承認が要る。** 承認を省略できる近道を作らない。

## うまくいかないとき

進行状況は `kba_get_job_status`、履歴は `kba_list_upload_jobs`。
症状ごとの対処は [references/upload-troubleshooting.md](references/upload-troubleshooting.md)。

権限や設定が足りずに止まった場合は、**返ってきた理由をそのまま利用者へ伝えて運用者に確認してもらう。**
設定変更を利用者に依頼しない。
