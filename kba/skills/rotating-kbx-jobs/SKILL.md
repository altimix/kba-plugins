# 月次で回す

掲載中の求人を分割し、毎月グループ単位で書き直して出し直す。**この skill 専用のツールは無い。**
やることは計画を立て、他の skill の手順を順に呼ぶこと。

## 最初にすること

```
kba_get_skill_guidance({ topic: "rotation" })
```

更新時の媒体仕様(変更しない列の扱い、給与の指定、ステータス遷移の制約)もここにある。
食い違ったら guidance に従う。

## 考え方

掲載中の全件を3つのグループに分け、毎月ひとつずつ回す。1周すると全件が新着として出し直される。

- グループの境界は初回に決めて記録しておく。CSV の中に持たない
- 1回あたりの件数は、写真 ID の割り当て上限に収まるようにする
- 回ごとに**訴求軸を変える**。同じ原稿を出し直しても新着として扱われにくい

## 手順

```
- [ ] 1. 今回のグループと対象求人を確定する
- [ ] 2. 前回と違う訴求軸を決める
- [ ] 3. 書き直す        → drafting-kbx-jobs
- [ ] 4. 確認して入稿する → revising-and-submitting-kbx-jobs
```

**1.** 対象は `kba_search_existing_jobs` で確認できる。現在の掲載状態は
`kba_list_kbox_csv_artifacts` → `kba_get_kbox_csv_artifact_rows`。

**2.** 前回どの軸で出したかを踏まえて変える。給与訴求で出したなら働き方訴求へ、といった具合。
型は drafting-kbx-jobs の reference にある。

**3-4.** それぞれの skill の手順に従う。**ここで別の手順を作らない。** 生成や入稿のやり方が
食い違うと、どちらが正しいか分からなくなる。

## 守ること

**既存求人の更新である。** 新規作成ではない。書き直す求人には `sourceJobId` を指定する。

**変更しない列は触らない。** 更新では、ヘッダーに含めた列を空欄にすると既存の値が消える。
変えない列はヘッダーごと省略する。詳しくは `kba_get_skill_guidance({ topic: "csv-spec" })`。

**ステータスの遷移には制約がある。** 募集停止にするときや募集停止のまま更新するときは、
他の項目を同時に変えられない。掲載保留は要因が解消するまで公開されない。

**重複を避ける。** 勤務先名 × タイトル × 勤務地_県 × 給与タイプ が既存と全部一致すると弾かれる。

**入稿は毎回、人の承認を通す。** 月次の定型作業でも承認を省略しない。

## 記録

どのグループをいつ回したか、どの訴求軸を使ったかを残す。次の周回で軸を変えるための材料になる。
CSV のメモ列には書かない。
