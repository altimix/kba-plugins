# 求人原稿をつくる

原稿の生成から、クライアント別 Google レビューシートへ載せるところまでを担う。**シートに載った時点で
この skill の仕事は終わり**で、そこから先は人が確認する。修正と入稿は別 skill。

## 最初にすること

運用ルールと媒体仕様はサーバが持っている。**作業に入る前に必ず取得する。**

```
kba_get_skill_guidance({ topic: "generation" })
kba_get_skill_guidance({ topic: "csv-spec" })
```

このファイルより guidance が新しい。食い違ったら guidance に従う。

## 手順

```
- [ ] 1. 対象クライアントを決める
- [ ] 2. 原典を読む(採用ページ / 求人票 / テキスト)
- [ ] 3. 写真の方針を確定する
- [ ] 4. 生成する
- [ ] 5. 結果を人に示す
- [ ] 6. レビューシートへ載せる
```

**1. 対象クライアント** — `kba_list_clients`。必要なら `kba_list_partners`。
既存の掲載求人を参考にするなら `kba_search_existing_jobs`。

**2. 原典** — 採用ページ URL / 求人票 PDF / テキストのいずれか。ここから事実を取る。

**3. 写真** — `kba_choose_csv_photo_policy` で「使わない / 登録済みを使う / 新しく作る」を一度で確定する。
画像を扱う手順そのものは preparing-kbx-photos に委ねる。ここで必要なのは、**求人ボックス側で有効になった写真ID**
(または「使わない」)だけ。

**4. 生成** — `kba_generate_csv_from_config` を **1回**呼ぶ。CSV 本文をモデル側で組み立てない。
ローカルスクリプトも使わない。引数の詳細はツールのスキーマにある。

既存求人のリライトでは `sourceJobId` を指定する。原典から自動で維持されるのは内部管理用の項目だけで、
給与・勤務地・雇用形態・勤務時間・応募資格・求人ステータスといった**内容の列は原典へ戻さない**。

**5. 結果** — チャットに示す。件数 / 確認したい項目(行・列・理由・推奨対応) / 重複リスク / 更新グループ。
別ファイルとして渡さない。

**6. シートへ** — `kba_append_generation_job_to_review_sheet`。生成で返った ID を内部でそのまま渡す。
**利用者に ID を転記させない。** 失敗したら生成物を保持したまま同じツールを再実行する。

進捗や結果の確認は `kba_get_job_status`。生成物の診断は `kba_get_csv_stats` / `kba_get_csv_rows` /
`kba_get_csv_row_diff`(**診断専用。編集の正本ではない**)。書き出しが要るときだけ
`kba_get_csv_download_url`。

## 守ること

**利用者が明示した値を最優先する。** 指定された値を、内容上の理由で書き換え・空欄化・既定値化・原典へ
復元しない。「おまかせ」「仮置き」のような明示的な委任も同じ扱いにする。選択肢の候補外でも、文字数を
超えていても、**値は変えずに警告として示す**。

**AI に任せた範囲だけ原典から転記する。** 給与・勤務地・雇用形態・勤務時間休日・勤務先名・応募条件・
派遣/紹介の法定表記は、根拠のない創作で埋めない。原典に無く指定も無ければ空欄にして確認に回す。

**内容の指摘は停止要因ではない。** 法令・媒体仕様・品質上の懸念は行・列・理由・推奨対応として示すが、
それだけで生成を止めない。利用者は確認したうえで、直すか「このまま進む」かを選べる。可否の最終判断は
求人ボックス側の応答で確認する。

**停止要因は別物。** 止まるのは、件数の不一致・CSV の構造破損・formula injection・認証や scope・
content hash や期限・人の承認、といった実行上のゲートだけ。

**求人ステータスは指示に従う。** 公開 / 下書き / 募集停止。**指示が無ければ空欄のまま出す。**
勝手に下書きへ落とさない。「公開のつもりが下書きになっていた」を防ぐための約束。

**勤務先名の公開設定は必ず確認する。** 非公開 / 公開 / 既存維持 のどれかを、生成前に利用者へ聞く。
既存求人でも3つとも選べる。

**編集の正本は Google レビューシート。** 生成結果のスナップショットを直接書き換えない。

**経路を混ぜない。** 生成器が保存済みなので、その結果を別のアップロード経路へ再送しない。

## 差分の作り方

同一求人と判定されないよう、タイトル・勤務地・給与・仕事内容に差分を作る。単純コピーを並べない。

原稿パターンの型、エリア配分、重複回避の組み合わせ設計は [references/drafting-patterns.md](references/drafting-patterns.md)。
1求人を複数候補へ分割する提案や競合差別化は `kba_get_skill_guidance({ topic: "split-differentiation" })`。

## つながらないとき

ツールが見つからない場合はコネクタが未接続。設定 → コネクタ → カスタムコネクタを追加 →
`https://mcp.kba.bazaarinc.dev/mcp`。別クライアントへの切り替えは operating-kbx-environment。
