# 原稿・エリア・件数の設計

同一求人と判定されないための差分のつけ方。**判断の型であって仕様ではない。** 文字数の目安、選択肢の
候補値、記号の扱いといった媒体仕様は `kba_get_skill_guidance({ topic: "csv-spec" })` が持っている。
食い違ったら guidance が正しい。

## 原稿パターン種別

| 種別 | ねらい | 主に変える場所 |
|---|---|---|
| 通常版 | 標準 | — |
| 短文版 | スマホで読み切れる | 仕事内容を圧縮 |
| 長文版 | ミスマッチ防止 | 仕事内容を拡充 |
| 未経験者向け | 未経験・初心者に届かせる | タイトル・冒頭・応募資格 |
| 経験者向け | スキルを活かせる点を訴求 | タイトル・仕事内容・給与表現 |
| 給与訴求版 | 条件を最前面に | タイトル先頭に給与 |
| 働き方訴求版 | 休日・シフト・リモート | タイトル・やりがい・仕事内容 |
| エリア訴求版 | 駅近・通いやすさ | タイトル・交通手段補足 |
| 1日の流れあり版 | 業務像を具体化 | 仕事内容に時系列を追加 |

件数が多いときは複数種別を混ぜる。同じ種別を連続させない。

## タイトルの作り分け

- 訴求軸(給与 / 働き方 / 未経験 / エリア)を変えると、実質的な差分になりやすい
- 語順の入れ替えだけ、記号の差し替えだけは差分として弱い
- 同一タイトルが連続していないかを最後に確認する

## 仕事内容の作り分け

- 短文版と長文版で情報量そのものを変える。同じ文を伸縮させただけにしない
- 1日の流れ、扱う商材、チーム構成のように**原典にある事実**で差をつける
- 原典に無いことを差分づくりのために創作しない

## エリア配分

利用者の指定があればそれに従う。無い場合の出発点:

| カテゴリ | 割合 | 主要エリア |
|---|---|---|
| 首都圏 | 40% | 東京23区・横浜・川崎・千葉・大宮 |
| 関西 | 20% | 大阪・神戸・京都・奈良 |
| 中部 | 15% | 名古屋・愛知各市 |
| その他政令市 | 15% | 福岡・札幌・仙台・広島 |
| その他 | 10% | 茨城・石川・静岡・熊本等 |

## 勤務地の書き方

県は都道府県名、詳細は市区町村＋丁目まで。

```
勤務地_県     : 東京都
勤務地_詳細   : 千代田区大手町1丁目
```

丁目までばらすと組み合わせが増え、重複判定を避けやすい。

## 組み合わせ数の設計

```
ユニーク組み合わせ数 = タイトル数 × 県数 × 丁目バリエーション数
```

目標件数以上のユニーク組み合わせを確保する。

```
タイトル10種 × 県10 × 丁目15 = 1,500通り
タイトル 8種 × 県10 × 丁目19 = 1,520通り
```

足りないまま件数を積むと重複リスクが上がる。足りない場合は結果に「重複リスクあり: N件」と明記する。

重複と判定されやすいのは **勤務先名 × タイトル × 勤務地_県 × 給与タイプ** が揃った組み合わせ。
既存の掲載求人との衝突は `kba_search_existing_jobs` で照合できる。

## 写真の割り当て

1つの写真 ID セットに紐づけられる件数には上限がある(上限値は `csv-spec` を参照)。件数が多いときは
セットを複数用意し、グループごとに割り当てる。

写真の用意そのもの(生成・登録・求人ボックスへの反映)は preparing-kbx-photos の担当。ここで扱うのは
**確定済みの写真 ID をどう配るか**だけ。

## 顧客確認が要る変更

次に手を入れるときは、生成前に利用者へ確認する。事後に「そんなつもりではなかった」となりやすい。

- 給与の表現を変える(範囲の見せ方、下限の強調)
- 応募資格の広さを変える(未経験可にする、経験年数を外す)
- 勤務先名の公開設定
- 派遣 / 紹介の法定表記に関わる部分
